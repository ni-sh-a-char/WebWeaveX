### Ranking rationale (per the PRIMARY RULE — risk/unlock over count)

- **Top pick next: `core.workflows` (7 APIs)** — largest clean cluster; the `save_*/load_*`
  members are roundtrip persistence (may need the `json.loads` substrate — confirm during
  analysis). The `run_*`/`build_*`/`replay_*` members are pure dict→envelope transforms like
  the connector family already proven, so most of the 7 land without new substrate.
- **High substrate value: the `core.crypto`/`core.session` cluster** — small (4–5 modules) but
  building the **JDK-only `json.loads` parser** it needs unlocks **every** `decrypt_*`/`load_*`
  roundtrip API across all clusters. Worth doing early as infrastructure even though it is only
  4 APIs, because it removes a recurring blocker.
- `core.execution`/`core.synchronization`/`core.evolution_runtime`/`core.causality` are each
  5–6 pure envelope APIs — high count, no new substrate — ideal mid-queue batches.
